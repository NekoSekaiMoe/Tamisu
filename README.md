Tamisu
======

Tamisu is a kernel-level Zygote implementation based on the KernelSU architecture and YukiSU's YukiZygisk implementation, but its goal is to be a GKI 2.0-compatible ZygiskNext Zygote injection implementation.

## Coexistence with other root / Zygisk implementations

Tamisu is a Zygisk provider, not a root provider. It is designed to
coexist with a separate root solution (KernelSU, Magisk, APatch, ...).

Zygisk injection has a strict priority order — only one provider may
inject into zygote, otherwise two PLT-hook frameworks in one process
corrupt each other and crash. Tamisu respects this automatically:

| Priority | Implementation | Behaviour |
|---|---|---|
| 1 | **Magisk Zygisk** | If Magisk's Zygisk toggle is on, Tamisu refuses to start its own zygiskd. |
| 2 | **Tamisu** | If active, Tamisu force-skips any independent zygisk module (`zygisksu` / `rezygisk` = ZygiskNext, NeoZygisk, ReZygisk) so they cannot race the kernel injection. |
| 3 | Module zygisk implementations | Yield to Tamisu (their scripts, sepolicy, props and zygisk payload are all skipped). |

Practical implications:
- **With Magisk**: turn Magisk's "Zygisk" toggle **off** in the Magisk
  app to let Tamisu handle zygisk. Leaving it on disables Tamisu's
  zygisk injection.
- **With KernelSU**: Tamisu and KernelSU can coexist out of the box
  (KernelSU manages root; Tamisu manages zygisk). The two use distinct
  driver fds (`[tamisu]` vs `[ksu_driver]`) and distinct ioctl magic
  (`'T'` vs `'K'`) so they do not interfere at the kernel interface.
- **Standalone**: Tamisu works on its own (it still needs a root
  provider for `su` access; use one of the above).
